# משימות CTO

כלי העבודה של צוות ה-CTO: אנשים מחליטים, Claude מבצע. עובד במחשב ובטלפון (אפשר להתקין כאפליקציה למסך הבית).

**כתובת:** https://cto-tasks.vercel.app

## המודל

לכל פרויקט יש מוביל ושותפים, ושלושה זרמים:

- **החלטות**: שאלה עם אפשרויות והמלצה, שמחכה לאדם. בוחרים בלחיצה, וההחלטה נרשמת ביומן ההחלטות עם הסיבה.
- **משימות Claude**: Claude מבצע ואדם אחראי. לכל משימה הגדרת סיום, ראיות והגשה לבדיקה. מוסתרות כברירת מחדל.
- **מטלות**: מה ש-Claude לא יכול לעשות: פגישה, קובץ, חיבור כלי, הזדהות, תשלום.

ולצידם **התחייבויות** לגורמים מחוץ לצוות (מה, למי, עד מתי), בשני הכיוונים.

מי מחליט:

- פתיחה או עצירה של פרויקט: המפקד. אחרי 3 ימי עבודה בלי תשובה ההחלטה פתוחה גם לסגן. פרויקט חדש נשאר "מוצע" עד ההחלטה.
- תעדוף בין פרויקטים: הפגישה השבועית.
- כל השאר: המוביל או השותפים בפרויקט.

## מסכים

| מסך | למה |
|---|---|
| מה מחכה לי | תור אחד: להחליט, לעשות, לבדוק. מה שחוסם מישהו למעלה, ולכל פריט כמה זמן הוא מחכה. בנוסף: על מה אני מחכה לאחרים. |
| המפקד בדקה | ההחלטות שמחכות למפקד, רק מה שעלה (כל פריט עם "עלה כי…"), ושורה לכל פרויקט עם פתיחה או עצירה בלחיצה. |
| החלטות | ההחלטות הפתוחות ויומן ההחלטות. |
| פרויקטים | כרטיסים או ציר זמן. בתוך פרויקט: הזרמים, טבלה, קנבן, ודף "על הפרויקט" עם אבני דרך, קישורים ותקציב זמן (2, 6 או 12 שבועות). |
| התחייבויות | מה הבטחנו ולמי, ועל מה מחכים מבחוץ. מה שבאיחור מסומן. |
| לוח צוות, דיילי, חסמים | העבודה הפתוחה לפי פרויקט, דיילי של 5 דקות עם מנחה מתחלף, ומה תקוע. |
| תמונת מצב | תצוגת הצוות: מספרים לצוות כולו בלבד, מה עלה ושורה לכל פרויקט. בלי ספירה או השוואה לפי אדם. |
| פגישה שבועית | 30 דקות מול המסך: החלטות, מצב הפרויקטים, תעדוף לשבוע הבא וסל הרעיונות. |
| דוח שבועי | טיוטה מהנתונים. השורה התחתונה והשליחה הן של המפקד, והדוח לא נשלח אף פעם אוטומטית. |

מה "עולה": החלטה, חסם או בדיקה שמחכים יותר משני ימי עבודה (ראשון עד חמישי), התחייבות שלנו שבאיחור או שמועד המסירה שלה קרוב, התחייבות כלפינו שבאיחור, ופרויקט בסיכון, שתקציב הזמן שלו נגמר, שאבן דרך שלו באיחור או שלא עודכן שבעה ימי עבודה.

כל פריט אפשר להעתיק כתדריך ל-Claude (כפתור "העתקה ל-Claude"), עם קובץ ההקשר של הצוות בראש.

הוספה מהירה בשורה אחת: `להכין מצגת @ירדן #פיילוט מחר !` יוצר מטלה עם אחראי, פרויקט, תאריך ועדיפות גבוהה. קיצורים במחשב: `n` חדש (מטלה, החלטה, משימת Claude, התחייבות, רעיון או פרויקט), `/` חיפוש.

## בלמ״ס

בלמ״ס בלבד. לפני כל שמירה הטקסט נבדק בדפדפן מול רשימת המילים הרגישות של הצוות, שנשמרת רק כטביעות אצבע (SHA-256) ואי אפשר לקרוא אותה בחזרה. כשיש התאמה הכלי עוצר ושואל. מה שנשמר בכל זאת מסומן כחשוד ומוסתר מכולם חוץ מהפיקוד עד בדיקה. פרויקט מסווג מחזיק רק שם בלמ״ס, מוביל ומצב.

## כניסה

קוד צוות אחד לכולם. מי שפותח את הכלי ראשון בוחר את הקוד (6 תווים לפחות) ושולח אותו לצוות בנפרד. אחרי זה כל אחד מזין את הקוד ובוחר את השם שלו. אפשר להחליף קוד מההגדרות. הקוד נשמר במסד רק כ-hash.

## התראות לטלפון

כל אחד מפעיל בהגדרות, בכל מכשיר בנפרד ("הפעלה במכשיר הזה"). באייפון זה עובד רק אחרי התקנה למסך הבית (iOS 16.4 ומעלה). לחיצה על התראה פותחת את הפריט עצמו.

- **מיד**: מטלה או משימה שהוקצתה, אחריות, החלטה שמחכה, התחייבות, אזכור, וחסם (גם למוביל הפרויקט). רק כשאדם עשה את הפעולה, לא סוכן.
- **תקציר יומי**: בימי עבודה בשעת התקציר (ברירת מחדל 08:00), עד 5 שורות ו"ועוד N".
- **תזכורות להתחייבויות**: 5 ימי עבודה ויום עבודה אחד לפני המועד. מסמנים "בזמן" או מעדכנים. תזכורת שלא נענתה תוך יום עבודה מעלה את ההתחייבות לצוות ולפיקוד.
- **שעות שקט**: 19:00 עד 08:00, ושישי ושבת כל היום (הפיקוד משנה בהגדרות). בשעות השקט לא יוצא כלום, חוץ מחסם בפרויקט שחייב משהו החוצה תוך יום עבודה.
- **המפקד**: רק החלטות שמחכות לו, בלי תקציר.
- פריט שמסומן כחשוד נשלח בלי הטקסט שלו: "פריט שמחכה לבדיקת הפיקוד".

התקציר והתזכורות הם **כללים קבועים** בלי AI: הטקסט שמאשרים בהגדרות הוא מה שרץ, כלל מתחיל לרוץ רק אחרי שאדם מהצוות אישר אותו, וכל ריצה נרשמת ביומן הריצות.

## עיצוב

כל המסכים, במחשב ובטלפון, בנויים לפי עקרונות העיצוב של אפל (מתוך "Designing Fluid Interfaces"), וזה הכלל לכל שינוי עד סוף הפרויקט. הפירוט ב-[`CLAUDE.md`](CLAUDE.md).

- **תנועה בקפיצים** (`app/motion.js`): כל מה שזז מתחיל מהמקום שלו על המסך, ממשיך במהירות של האצבע, ואפשר לתפוס אותו באמצע. בטלפון גוררים גיליון למטה כדי לסגור אותו, או מעיפים אותו בתנועה מהירה. דיאלוג גדל מהנקודה שנלחצה, תפריט יוצא מהכפתור שפתח אותו, וכל שכבה יוצאת באותו מסלול שבו נכנסה.
- **תגובה מיידית**: כפתור מגיב ברגע הלחיצה, לא בשחרור.
- **מראה**: גופן המערכת, צבעי המערכת של אפל, משטחים מקובצים, סטטוס בכמוסה צבעונית, וזכוכית רק לסרגלים שהתוכן נגלל מתחתם.
- **נגישות**: תנועה מופחתת מחליפה החלקות בהופעה הדרגתית, שקיפות מופחתת הופכת את הזכוכית לאטומה, וניגודיות גבוהה מוסיפה קווי מתאר.

## איך זה בנוי

- **אתר סטטי בלי שלב build**: מודולי ES, [Preact](https://preactjs.com) ו-[htm](https://github.com/developit/htm) שמורים ב-`app/lib`. אין `npm install`.
- **מסד נתונים**: Supabase Postgres. כל הטבלאות מוגנות ב-RLS שבודק את קוד הצוות שנשלח בכותרת `x-team-code`. טריגרים כותבים את יומן הפעילות וההתראות, ומחילים החלטת פתיחה או עצירה על הפרויקט. הסכמה: [`supabase/schema.sql`](supabase/schema.sql) (תמונה מ-13/10), ועליה המיגרציות ב-[`supabase/migrations`](supabase/migrations) לפי הסדר.
- **אחסון**: Vercel. ב-`vercel.json` יש rewrite מ-`/sb/*` ל-Supabase, כך שהדפדפן מדבר רק עם אותו דומיין.
- **PWA**: `manifest.webmanifest` ו-`sw.js` (קבצי האפליקציה זמינים גם בלי רשת; הנתונים תמיד חיים).
- **התראות לטלפון**: Web Push רגיל, בלי ספריות ובלי שירות חיצוני. פונקציית Edge בשם `push` ב-[`supabase/functions/push`](supabase/functions/push) מצפינה כל הודעה לפי RFC 8291 וחותמת לפי RFC 8292 (VAPID). המפתחות נוצרים בקריאה הראשונה ונשמרים במסד. המסד קורא לפונקציה: טריגר על ההתראות למה שיוצא מיד, ו-pg_cron כל שעה לתקציר ולתזכורות. שירותי ההתראות של אפל, גוגל ומוזילה מקבלים רק תוכן מוצפן.
- **שמירה על המסד ער**: Supabase בתוכנית החינמית משהה פרויקט אחרי שבוע בלי מספיק פעילות. שתי משימות cron ב-`vercel.json` קוראות כל יום ל-`api/keepalive.js`, שמריץ כמה שאילתות קלות דרך `/sb`. אפשר לפתוח את https://cto-tasks.vercel.app/api/keepalive כבדיקת בריאות: `"ok": true` אומר שהאתר, הפרוקסי והמסד עובדים.


## החיבור ל-Claude (המחבר)

שרת MCP שדרכו ה-Claude של כל אחד ואחת עובד מול הפלטפורמה, בשני הכיוונים. הקוד ב-`supabase/functions/mcp/` (`server.js` הוא כל השרת, ורץ גם ב-Node לבדיקות), והכתובת לכל אדם היא `https://cto-tasks.vercel.app/mcp/cto_…` עם המפתח האישי שלו (Vercel מעביר את `/mcp/*` לפונקציה).

- **Claude → פלטפורמה:** `start_run`, `report_progress`, `publish_output` (תוצר עם קישור, מחכה לאישור), `ask_decision` (כרטיס החלטה והתראה), `request_human_step` (מטלה אנושית), `finish_run`.
- **פלטפורמה → Claude:** `whats_waiting`, `get_updates` ותשובת `report_progress` מחזירים החלטות שהתקבלו, מטלות שבוצעו, הערות על תוצרים, בקשות עצירה, ומשימות שהופעלו ממרכז הבקרה (ריצה במצב `queued`, ש-Claude אוסף עם `start_run` וה-`run_id`).
- **כללים:** הכתיבה נעשית בשם סוכן ה-Claude של הצוות, אז כללי הסוכן במסד חלים: הוא לא מחליט, לא סוגר, לא מאשר תוצר, לא מוחק ולא מבטל עצירה של אדם. כל טקסט עובר את בדיקת הבלמ״ס.
- **מפתחות:** כל אדם יוצר מפתח לעצמו במרכז הבקרה (`/next/`, "חיבור ל-Claude"). נשמר רק ה-SHA-256 שלו, ועד 5 פעילים לאדם.
- **כבוי עד שמפעילים:** `team_settings.connector_enabled` מתחיל ב-`false`, והמחבר מחזיר 403 עד שהצוות מפעיל אותו.

הפעלה, פעם אחת: להריץ את המיגרציה `20261014050000_claude_connector.sql`, להעלות את הפונקציה עם `supabase functions deploy mcp --no-verify-jwt` (היא מזהה לפי המפתח האישי, לא לפי JWT), ואז `update team_settings set connector_enabled = true;`.


`?mock` מריץ את כל הכלי מול נתוני דוגמה בדפדפן בלבד. בלי `?mock` הכלי פונה ל-`/sb`, שעובד רק דרך Vercel.

## פריסה

הפרויקט ב-Vercel הוא `cto-tasks` (סטטי, בלי framework ובלי build, חוץ מהפונקציה ב-`api/`). כל פריסה מעלה את הקבצים כמו שהם. משימות ה-cron רצות רק בפריסת הייצור.

התראות לטלפון צריכות פעם אחת, אחרי המיגרציה `20261014040000_push.sql`:

1. לשמור את כתובת הפרויקט: `insert into private.settings (key, value) values ('project_url', 'https://<project-ref>.supabase.co');`
2. להעלות את הפונקציה: `supabase functions deploy push --no-verify-jwt` (היא בודקת בעצמה סוד משותף שרק המסד מחזיק).
3. לבדוק: `GET /sb/functions/v1/push` מחזיר את המפתח הציבורי, והמשימה `push-hourly` מופיעה ב-`cron.job`.

הפונקציה מקבלת בלי סוד רק שלוש בקשות: המפתח הציבורי, התראת בדיקה והתקציר שלי עכשיו, ושתי האחרונות נשלחות רק למכשיר ששלח את הבקשה. שליחה של התראה או של התקציר היומי דורשת את הסוד בכותרת `x-push-secret`.

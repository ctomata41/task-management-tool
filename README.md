# משימות CTO

כלי העבודה של צוות ה-CTO: אנשים מחליטים, Claude מבצע. עובד במחשב ובטלפון (אפשר להתקין כאפליקציה למסך הבית).

**כתובת:** https://cto-tasks.vercel.app

## המודל

לכל פרויקט יש מוביל ושותפים, ושלושה זרמים:

- **החלטות**: שאלה עם אפשרויות והמלצה, שמחכה לאדם. בוחרים בלחיצה, וההחלטה נרשמת ביומן ההחלטות עם הסיבה.
- **משימות Claude**: Claude מבצע ואדם אחראי. לכל משימה הגדרת סיום, ראיות והגשה לבדיקה. מוסתרות כברירת מחדל.
- **מטלות**: מה ש-Claude לא יכול לעשות: פגישה, קובץ, חיבור כלי, הזדהות, תשלום.

ולצידם **התחייבויות** לגורמים מחוץ לצוות (מה, למי, עד מתי), בשני הכיוונים.

מי מחליט:

- פתיחה או עצירה של פרויקט: המפקד. אחרי 3 ימי עבודה בלי תשובה ההחלטה פתוחה גם לסגן. פרויקט חדש נשאר "מוצע" עד ההחלטה.
- תעדוף בין פרויקטים: הפגישה השבועית.
- כל השאר: המוביל או השותפים בפרויקט.

## מסכים

| מסך | למה |
|---|---|
| מה מחכה לי | תור אחד: להחליט, לעשות, לבדוק. מה שחוסם מישהו למעלה, ולכל פריט כמה זמן הוא מחכה. בנוסף: על מה אני מחכה לאחרים. |
| המפקד בדקה | ההחלטות שמחכות למפקד, רק מה שעלה (כל פריט עם "עלה כי…"), ושורה לכל פרויקט עם פתיחה או עצירה בלחיצה. |
| החלטות | ההחלטות הפתוחות ויומן ההחלטות. |
| פרויקטים | כרטיסים או ציר זמן. בתוך פרויקט: הזרמים, טבלה, קנבן, ודף "על הפרויקט" עם אבני דרך, קישורים ותקציב זמן (2, 6 או 12 שבועות). |
| התחייבויות | מה הבטחנו ולמי, ועל מה מחכים מבחוץ. מה שבאיחור מסומן. |
| לוח צוות, דיילי, חסמים | העבודה הפתוחה לפי פרויקט, דיילי של 5 דקות עם מנחה מתחלף, ומה תקוע. |
| תמונת מצב | תצוגת הצוות: מספרים לצוות כולו בלבד, מה עלה ושורה לכל פרויקט. בלי ספירה או השוואה לפי אדם. |
| פגישה שבועית | 30 דקות מול המסך: החלטות, מצב הפרויקטים, תעדוף לשבוע הבא וסל הרעיונות. |
| דוח שבועי | טיוטה מהנתונים. השורה התחתונה והשליחה הן של המפקד, והדוח לא נשלח אף פעם אוטומטית. |

מה "עולה": החלטה, חסם או בדיקה שמחכים יותר משני ימי עבודה (ראשון עד חמישי), התחייבות שלנו שבאיחור או שמועד המסירה שלה קרוב, התחייבות כלפינו שבאיחור, ופרויקט בסיכון, שתקציב הזמן שלו נגמר, שאבן דרך שלו באיחור או שלא עודכן שבעה ימי עבודה.

כל פריט אפשר להעתיק כתדריך ל-Claude (כפתור "העתקה ל-Claude"), עם קובץ ההקשר של הצוות בראש.

הוספה מהירה בשורה אחת: `להכין מצגת @ירדן #פיילוט מחר !` יוצר מטלה עם אחראי, פרויקט, תאריך ועדיפות גבוהה. קיצורים במחשב: `n` חדש (מטלה, החלטה, משימת Claude, התחייבות, רעיון או פרויקט), `/` חיפוש.

## בלמ״ס

בלמ״ס בלבד. לפני כל שמירה הטקסט נבדק בדפדפן מול רשימת המילים הרגישות של הצוות, שנשמרת רק כטביעות אצבע (SHA-256) ואי אפשר לקרוא אותה בחזרה. כשיש התאמה הכלי עוצר ושואל. מה שנשמר בכל זאת מסומן כחשוד ומוסתר מכולם חוץ מהפיקוד עד בדיקה. פרויקט מסווג מחזיק רק שם בלמ״ס, מוביל ומצב.

## כניסה

קוד צוות אחד לכולם. מי שפותח את הכלי ראשון בוחר את הקוד (6 תווים לפחות) ושולח אותו לצוות בנפרד. אחרי זה כל אחד מזין את הקוד ובוחר את השם שלו. אפשר להחליף קוד מההגדרות. הקוד נשמר במסד רק כ-hash.

## איך זה בנוי

- **אתר סטטי בלי שלב build**: מודולי ES, [Preact](https://preactjs.com) ו-[htm](https://github.com/developit/htm) שמורים ב-`app/lib`. אין `npm install`.
- **מסד נתונים**: Supabase Postgres. כל הטבלאות מוגנות ב-RLS שבודק את קוד הצוות שנשלח בכותרת `x-team-code`. טריגרים כותבים את יומן הפעילות וההתראות, ומחילים החלטת פתיחה או עצירה על הפרויקט. הסכמה: [`supabase/schema.sql`](supabase/schema.sql) (תמונה מ-13/10), ועליה המיגרציות ב-[`supabase/migrations`](supabase/migrations) לפי הסדר.
- **אחסון**: Vercel. ב-`vercel.json` יש rewrite מ-`/sb/*` ל-Supabase, כך שהדפדפן מדבר רק עם אותו דומיין.
- **PWA**: `manifest.webmanifest` ו-`sw.js` (קבצי האפליקציה זמינים גם בלי רשת; הנתונים תמיד חיים).
- **שמירה על המסד ער**: Supabase בתוכנית החינמית משהה פרויקט אחרי שבוע בלי מספיק פעילות. שתי משימות cron ב-`vercel.json` קוראות כל יום ל-`api/keepalive.js`, שמריץ כמה שאילתות קלות דרך `/sb`. אפשר לפתוח את https://cto-tasks.vercel.app/api/keepalive כבדיקת בריאות: `"ok": true` אומר שהאתר, הפרוקסי והמסד עובדים.

```
index.html            מעטפת + import map
app/main.js           ניווט, התראות, חיפוש, הוספה מכל מקום
app/store.js          מצב גלובלי, טעינה כל 20 שניות, כתיבה אופטימית
app/model.js          המודל: התור "מה מחכה לי", מה עולה, ימי עבודה, מי מחליט
app/guard.js          בדיקת המילים הרגישות לפני שמירה
app/export.js         "העתקה ל-Claude" וייצוא מלא
app/api.js            לקוח REST ל-Supabase + מסד מדומה לבדיקות (?mock)
app/ui.js             רכיבים משותפים
app/views/*.js        המסכים
app/styles.css        עיצוב (בהיר/כהה, RTL, מובייל מתחת ל-900px)
api/keepalive.js      בדיקת בריאות שרצה פעמיים ביום ושומרת את המסד ער
```

## פיתוח מקומי

```sh
npx http-server -c-1 .
# http://localhost:8080/?mock   מסד מדומה בזיכרון, בלי לגעת בנתונים האמיתיים
```

`?mock` מריץ את כל הכלי מול נתוני דוגמה בדפדפן בלבד. בלי `?mock` הכלי פונה ל-`/sb`, שעובד רק דרך Vercel.

## פריסה

הפרויקט ב-Vercel הוא `cto-tasks` (סטטי, בלי framework ובלי build, חוץ מהפונקציה ב-`api/`). כל פריסה מעלה את הקבצים כמו שהם. משימות ה-cron רצות רק בפריסת הייצור.
